# FeastFlow — Strict Post-Migration Verification & 1:1 Parity Audit

The React + Tailwind migration has already been implemented.

DO NOT perform another migration.

DO NOT redesign anything.

DO NOT improve the UI.

DO NOT add features.

DO NOT modify the backend.

DO NOT modify the database.

DO NOT modify APIs.

DO NOT modify authentication logic.

DO NOT modify business logic.

Your task now is ONLY to perform a comprehensive verification and parity audit of the migrated React frontend against the original frontend.

## 1. FIRST: COMPARE OLD VS NEW

Inspect both:

* Original HTML/CSS/JavaScript frontend
* New React/Tailwind frontend

Create a complete mapping:

Original page → React page
Original JS module → React component/hook/service
Original CSS → Tailwind implementation
Original API call → React API service
Original Socket.IO logic → React Socket.IO implementation
Original Leaflet logic → React map component

Do not assume anything is equivalent just because the React page renders.

Verify actual behavior.
